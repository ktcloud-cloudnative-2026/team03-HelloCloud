# document API

[← API 명세](README.md) · 데이터: [데이터 구조](../erd/document.md)

## 1. 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 동시 편집 | Yjs + Hocuspocus | 동시에 고쳐도 내용을 합쳐 줍니다(US-28) |
| 편집 권한 | 조직 멤버 모두 | 요구사항과 같고 단순합니다. **포기하는 점:** 읽기 전용 문서가 없습니다 |
| 삭제 권한 | 만든 사람 또는 OWNER | 실수로 지우는 일을 줄입니다 |

## 2. 외부 API

모두 로그인 토큰과 조직 소속이 필요합니다.

| 주소 | 권한 | 하는 일 | 성공 | 에러 | 요구사항 |
|---|---|---|---|---|---|
| `GET /api/documents?orgId=` | 멤버 | 문서 목록 | 200 | 403 | US-28 |
| `POST /api/documents` | 멤버 | 문서나 드로잉 생성 | 201 | 400, 403 | US-28 |
| `GET /api/documents/{id}` | 멤버 | 문서 정보 조회 | 200 | 403, 404 | US-28 |
| `PATCH /api/documents/{id}` | 멤버 | 제목 수정 | 200 | 400, 403, 404 | US-28 |
| `DELETE /api/documents/{id}` | 만든 사람 또는 OWNER | 삭제 | 204 | 403, 404 | US-28 |
| `WS /api/documents/{id}/ws` | 멤버 | 공동 편집 연결. Hocuspocus 형식 | 연결 | 401, 403, 404 | US-28 |

### 요청과 응답 예시

`POST /api/documents`

```json
{ "orgId": "1", "type": "DRAWING", "title": "아키텍처 스케치" }
```

```json
{ "id": "6721f0a3", "orgId": "1", "type": "DRAWING", "title": "아키텍처 스케치", "createdBy": "3f2c8e1a-...", "updatedAt": "2026-11-06T09:00:00+09:00" }
```

## 3. 공동 편집 순서

1. 브라우저가 WebSocket으로 연결하고 Hocuspocus의 인증 기능으로 로그인 토큰을 보냅니다.
2. 서비스가 토큰과 조직 소속을 확인합니다.
3. MongoDB에서 `yjsState`를 읽어 편집을 시작합니다.
4. 변경 내용은 다른 사용자에게 바로 전달하고, MongoDB에 저장합니다.
5. 서버가 여러 대이면 Hocuspocus의 Redis 기능으로 서버끼리 맞춥니다.

멤버 제거 알림을 받으면 그 사용자의 연결을 끊습니다.

## 4. 내부 API

없습니다.

## 5. 만들 때 확인할 것

- 두 사용자가 동시에 고쳐도 내용이 사라지지 않는지(US-28)
- 변경이 3초 안에 다른 화면에 보이는지(US-28)
- 서버를 재시작해도 내용이 유지되는지(US-28)
- Keycloak 확인과 MongoDB 저장을 Hocuspocus에 실제로 연결할 수 있는지
- 큰 문서가 16MB 제한에 가까워지는지

## 6. 이번에 만들지 않는 것

문서 권한 설정, 버전 기록, 댓글, 템플릿 마켓은 빼두었습니다. 편집기와 드로잉 도구는 담당자가 구현하면서 정합니다.
