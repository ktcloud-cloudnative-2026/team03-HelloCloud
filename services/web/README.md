# React + Vite

이 템플릿은 Vite에서 React를 HMR(코드를 고치면 새로고침 없이 화면에 바로 반영하는 기능)과 몇 가지 ESLint 규칙으로 실행하기 위한 최소 설정을 제공합니다.

## 로컬 실행

`http://localhost:5173`은 `npm run dev`를 실행한 그 PC에서만 열립니다.

1. `services/web`에서 `npm install` (처음 한 번)
2. `cp .env.example .env.local` — 로컬 Keycloak(`services/compose.yaml`, `http://localhost:8180`)을 쓰게 합니다
3. `npm run dev` → 터미널에 나온 주소로 접속 (터미널을 끄면 꺼집니다)
4. 로그인·조직 목록·만들기까지 보려면 Keycloak과 user-service(8081)도 켜야 합니다. 순서는 `services/user-service/README.md`

## 로그인 (Keycloak)

로그인 버튼을 누르면 Keycloak 로그인 화면으로 이동하고, 돌아오면 API 요청에 로그인 토큰을 붙입니다.
토큰은 만료 30초 전에 자동으로 갱신하고, 갱신이 안 되거나 API가 401을 주면 다시 로그인 화면으로 보냅니다.
조직 선택 화면과 대시보드의 로그아웃 버튼은 Keycloak 세션까지 끝내고 첫 화면으로 돌아옵니다.

Keycloak 로그인 라이브러리(keycloak-js)는 브라우저의 암호화 기능을 쓰므로 **HTTPS나 `localhost`에서만** 동작합니다.
dev(`http://10.10.24.101`)는 아직 HTTPS가 없어서, 접속용 크롬을 띄울 때 이 주소를 안전한 주소로 취급하게 합니다.
먼저 다른 창에서 `ssh -N -D 1080 t4-dev-cp`로 터널을 열어 둡니다.

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --proxy-server="socks5://localhost:1080" `
  --unsafely-treat-insecure-origin-as-secure="http://10.10.24.101" --user-data-dir="$env:TEMP\chrome-t4"
```

dev에 HTTPS를 붙이면 이 옵션은 필요 없습니다.

## 팀원 초대와 멤버 관리

조직 OWNER는 대시보드의 "팀원 초대" 버튼으로 초대 링크(`/invite/<토큰>`)를 만들어 복사합니다.
링크를 연 사람은 로그인한 뒤 "초대 수락하기"를 눌러 MEMBER로 가입합니다. 링크는 한 번만 쓸 수 있습니다.
이 주소를 웹이 받으려고 `nginx.conf`는 파일이 없는 주소에 `index.html`을 돌려줍니다.

대시보드 사이드바의 "멤버"에서 조직 멤버를 봅니다. OWNER는 다른 멤버를 내보낼 수 있고, MEMBER는 조직을 나갈 수 있습니다.

현재 공식 플러그인은 두 가지가 있습니다.

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react): [Oxc](https://oxc.rs)를 사용합니다.
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc): [SWC](https://swc.rs/)를 사용합니다.

## ESLint 설정 확장

실제 서비스용 애플리케이션을 개발한다면 TypeScript를 쓰고, 타입 정보를 활용하는 린트 규칙을 켜는 것을 권장합니다. 프로젝트에 TypeScript와 [`typescript-eslint`](https://typescript-eslint.io)를 적용하는 방법은 [TS 템플릿](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts)을 참고하세요.

## 파일 API 연동

파일 화면은 로그인 토큰과 선택한 조직 ID로 목록을 요청합니다. 업로드 시작 API → 서명 URL로 PUT → 완료 API 순서로 처리하며, 완료 후 첫 페이지를 다시 불러옵니다. 파일 상한은 백엔드와 같은 100,000,000바이트입니다. 다운로드는 API가 발급한 임시 URL을 사용하며 저장소에는 로그인 토큰을 보내지 않습니다.

팀 dev에서 확인할 순서: 로그인 → 조직 선택 → 파일 관리 → 빈 목록 또는 파일명 확인 → 작은 파일 업로드 → 목록에 표시 → 다운로드한 원본 내용 비교. 목록 요청 실패 시 재시도 버튼과 파일 선택을 확인합니다. 실패한 업로드의 임시 데이터 자동 정리는 백엔드 후속 범위입니다.

로컬 웹의 기본 API 프록시는 user-service(8081)이고, `/api/chat`은 chat(3000)으로 WebSocket까지 넘깁니다. 팀 dev의 파일 API를 시험할 때는 dev 웹과 dev 로그인 계정을 사용합니다. 로컬 Keycloak 토큰을 dev API에 보내지 않습니다.

### 파일 미리보기

파일 목록에서 PNG·JPEG·GIF·WebP·AVIF·PDF에 미리보기 버튼을 표시합니다. 버튼을 누를 때마다 로그인 토큰으로 미리보기 URL을 새로 발급받아 새 탭에서 엽니다. 저장소로 로그인 토큰을 전달하지 않습니다. SVG·Office·텍스트 등은 다운로드 안내를 표시합니다. 주소 발급 실패나 팝업 차단은 파일 화면에 안내하며, 발급 실패 시 빈 탭을 닫습니다.

dev 확인: 이미지와 PDF를 업로드하고 미리보기로 열리는지, TXT에는 다운로드 안내가 나오는지 확인합니다. 이는 파일 목록 미리보기이며 US-08의 채팅 채널 연결은 별도입니다.

### 파일 삭제

현재 로그인한 업로더 또는 조직 OWNER에게만 삭제 버튼을 표시합니다. 파일명을 포함한 확인창에서 동의해야 DELETE API를 호출하며 서버가 최신 권한을 다시 검사합니다. 성공 후 목록을 다시 불러오고 페이지의 마지막 파일이었다면 이전 페이지로 이동합니다. 실패 시 파일을 화면에서 임의로 지우지 않으며 권한 변경·없는 파일·저장소 오류를 안내합니다.

dev 검증에는 삭제해도 되는 시험 파일만 사용합니다. 업로더·OWNER의 삭제 성공, 다른 MEMBER에게 버튼 미표시, 확인창 취소, 삭제 후 목록·새로고침 결과를 확인합니다. 다른 조직/탈퇴 계정의 API 403과 저장소 객체 삭제 여부는 백엔드 담당자와 별도로 확인합니다. 화면의 버튼 숨김만으로 서버 권한 검증을 완료했다고 판단하지 않습니다.

파일 목록에는 수동 새로고침과 페이지 번호가 있습니다. 다른 사용자의 삭제로 페이지가 비면 마지막 유효 페이지로 이동합니다. 업로드 전 빈 파일·100MB 상한·파일명 제한을 서버와 동일하게 확인하고 작은 파일은 B/KB로 표시합니다. 최종 서버 권한과 저장소 상태는 dev에서 시험 계정·시험 파일로 확인합니다.

#### 삭제 화면 사전 검증 (2026-11-18)

자동 테스트와 별도로 개인용 가짜 데이터 화면에서 다음을 확인했습니다. 실제 팀 서버나 저장소 파일은 변경하지 않았으며 개인 예시는 Git 추적 대상이 아닙니다.

- MEMBER는 자기 파일만 삭제 버튼 표시, OWNER는 다른 멤버 파일에도 표시.
- 확인창 취소 시 파일 유지, 삭제 중 버튼 비활성화, 성공 후 개수와 목록 갱신.
- API 403 시 권한 변경 안내와 파일 유지.
- 21개 목록의 마지막 페이지에서 한 파일 삭제 후 첫 페이지 20개로 복귀.
- 목록 503 이후 재시도 성공, 390px 화면에서 버튼 겹침 없음.

dev 최종 검증은 한 번의 배포 후 시험 파일로 수행합니다. 업로더의 취소/삭제, OWNER의 타인 시험 파일 삭제, 다른 MEMBER의 버튼 미표시와 직접 API 403, 재조회 후 결과 유지, 기존 업로드/미리보기/다운로드를 확인합니다. 다른 조직 접근 차단과 저장소 객체 삭제는 백엔드 담당자와 함께 확인해야 하며 로컬 예시 결과로 대신하지 않습니다.

## 채팅

채팅 메뉴는 조직의 채널 목록 · 만들기, 메시지 보내기, 실시간 받기를 합니다. 메시지 보내기는 HTTP, 받기는 WebSocket(`/api/chat/ws`)입니다([chat API](../../docs/api/chat.md)).

- 내가 보낸 메시지는 HTTP 응답과 WebSocket으로 두 번 오므로 `id`로 한 번만 보여 주고 `seq` 순서로 정렬합니다
- 연결이 끊기면 1 · 2 · 4 · 8초, 이후 10초 간격으로 다시 연결합니다. 다시 구독되면 마지막 `seq` 이후를 조회해 놓친 메시지를 채웁니다(US-07). 처음 들어갈 때도 같은 방법으로 최근 500개까지 불러옵니다
- 로그인 토큰이 만료되기 1분 전에 새 토큰을 보내 연결을 이어 갑니다
- 조직에서 내보내지면 서버가 연결을 끊고(`Membership revoked`), 화면은 다시 연결하지 않고 안내를 띄웁니다(US-04)
- Enter로 보내고 Shift+Enter로 줄을 바꿉니다. 한글 조합 중 Enter는 보내지 않습니다
- 입력창 왼쪽 `@`로 확인을 요청할 멤버를 고릅니다(최대 20명). 받은 사람에게는 "확인했어요" 버튼이, 보낸 사람에게는 "확인 m/n"이 보이고 누르면 누가 아직 안 봤는지 나옵니다(US-11)
- 메시지 아래 `☺+`로 이모지(👍 ✅ ❤️ 😂 🎉 👀)를 달고, 다시 누르면 취소합니다. 바뀐 내용은 `MESSAGE_UPDATED`로 다른 사람 화면에도 바로 반영됩니다
- 메시지 아래 "📌 고정하기"를 누르면 채널 목록 위의 "📌 고정 메시지"에 모입니다(API·요구사항 이름은 결정 로그, US-10). 메시지마다 작성자 · 고정한 사람 · 시각이 보이고, "원본 보기"를 누르면 그 채널로 옮겨 원본 메시지를 잠깐 강조합니다. 같은 메시지는 한 번만 고정됩니다
- 입력창 왼쪽 `📎`로 조직 파일을 고르거나 새로 올려 붙입니다(최대 5개, 글 없이 첨부만 보내도 됩니다). 메시지의 이미지는 "미리보기"를 누르면 채널 안에 바로, PDF는 새 탭으로 열리고, 그 밖은 내려받기만 있습니다(US-08). 주소는 누를 때마다 새로 받으며 저장소에 로그인 토큰을 보내지 않습니다

dev 확인: 두 브라우저(또는 시크릿 창)에서 다른 계정으로 같은 채널을 열고 서로 메시지를 보냅니다. 한쪽에서 개발자 도구 → 네트워크를 오프라인으로 바꿨다가 되돌린 뒤 그사이 온 메시지가 보이는지, OWNER가 다른 쪽을 내보내면 안내가 뜨는지 확인합니다.
